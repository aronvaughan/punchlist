# av-tasks — PRD (v1)

*Step 2 of the build plan. What we're building and for whom. See
2026-08-23-product-analysis.md for why we're building at all.*

## Users

1. **Aron (human)** — phone (iPhone Safari over tailnet) and desktop
   browser. Wants Things-ish feel: fast list UI, drag-and-drop, quick add,
   nothing to babysit.
2. **Claude Code & Hermes (agents)** — first-class users via the REST API
   wrapped in an `av-tasks` skill each. They triage the Inbox, add tasks
   from conversations/email, report what's due, complete items, and file
   tasks under domains.

## Core model

- **When vs due (Things model, refined):** every task has an optional
  `when` — a date ("surface it that day"), `someday` (parked), or empty
  (anytime). A when-date **arrives**: once it is today or past, the task
  sits in Today until done or rescheduled — no silent rollover. `due` is a
  pure deadline. Today view = arrived-when tasks + anything due
  today/overdue (shown with a deadline chip explaining why it's there).
- **Project sections (fixed order):** TODAY (manual order) → UPCOMING
  (by when date) → ANYTIME (no when, manual order) → SOMEDAY (end, dimmed
  but visible). Dragging between sections edits `when` (to Today sets
  when=today; to Someday parks). The list IS the control.
- **Inbox graduation:** a task leaves Inbox when it gains a project OR a
  when.
- **Project hierarchy:** projects have an optional `parent` project —
  grouping projects under a domain/parent (Things "Areas"). Rail shows
  the tree.

- **Task** — title, notes (markdown), due date (date, optional time),
  status (inbox | active | done | archived), tags [*], project ref,
  ordering rank, recurrence rule (optional), timestamps, `created_by`
  (aron | claude | hermes).
- **Step** — ordered checklist item inside a task (title + done). Steps
  are not tasks (no dates/tags) — Things-style.
- **Project** — named container, mapped 1:1 where sensible to a DOMAINS
  entry (`domain` field holds the registry name); has its own ordered task
  list and an "someday/later" flag per task via status.
- **Inbox** — the projectless triage bucket; new tasks land here unless a
  project is given.
- **Recurrence** — small explicit set: `daily | weekly(days) |
  monthly(day-of-month) | every N days`, with two anchors:
  `due_anchored` (next occurrence's due ticks on schedule from the DUE
  date, even when completed late — "spawn on time") or
  `completion_anchored` (next due = completion date + interval).
  Completing a recurring task spawns the next occurrence; the spawn gets
  `when` = its new due date by default.

## User stories (v1)

Human:
1. Quick-add a task from any screen (title + optional `#tag @project
   !due` tokens) in under 3 seconds.
2. See Today (due/overdue), Inbox, and any Project as lists; drag to
   reorder within a list; drag Inbox items onto a project to file them.
3. Open a task: edit fields, check off steps, complete, archive.
4. Create a recurring task ("water plants every 3 days") and trust it.

Agents:
5. `add` a task (with steps/tags/project/due) and get its id.
6. `list` by view (inbox | today | overdue | project X | tag Y) as JSON.
7. `complete` / `update` / `move` a task by id.
8. `projects` — list projects + domains so filing matches the registry.
9. On "hermes, what should I do today?" — answer from the API, not memory.

## Things-parity calls (2026-08-23 review)

Explicitly IN (v1): Logbook (completed view, rail item); project notes
field; Mail-to-Inbox (email the agents' mail account → hermes files a task);
tag filter chips on any list; full-text search across titles + notes (`/`).

Explicitly OUT (v1, revisit only with usage evidence): This Evening;
headings inside projects (when-sections cover it); time-of-day reminders/
alerts; calendar integration; separate Trash (delete = archive, restic
behind it); Siri/widgets/native apps; progress pies; collaboration.

## Non-goals (v1)

Multi-user/sharing, push notifications (agents nag via Telegram),
attachments, comments, offline-first sync, calendar integration, mobile
native app. Revisit in v2 only with real usage evidence.

## Experience notes

- One-page web app; left rail: Inbox / Today / Upcoming / Projects;
  main pane: task list; detail as slide-over. Keyboard: `n` new task,
  `/` search. Mobile: same page, rail collapses to tabs; drag still works
  (SortableJS touch).
- Fast is a feature: p95 < 150ms API on the LAN, list paint < 1s on phone.

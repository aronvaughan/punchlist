# punchlist 1.1.0 — the process spine

2026-09-30 · stable · npm dist-tag: `latest`

## Highlights
- **The process spine.** `plt` now runs a card from scope to merge as a run of a cycle formula. Each step keeps receipts and pins the commit it ran on. A person approves each human gate with a yes or a no.
- **Parallel work that stays safe.** An effort groups cards. `plt effort plan` and `plt fan` compute the wave of cards that can run at once. Run locks, per-window claims, `plt fsck` and `plt doctor` protect and check the run files.
- **Boards you can read.** `plt render` writes an effort index and a page per run. The index shows a panel per effort, a needs-a-human strip and estimate against actual. `plt publish` tells you which pages to publish.
- **Two new cycles for delivery.** Use `build-and-ship` for pull requests and `build-and-commit` for projects that review commits. Three new adversary agents review code, architecture and plans.
- **Global installs keep their data.** A global npm install now stores its database in `~/.local/share/punchlist`, and `plt` works from the npm package. **Read the upgrade steps before you upgrade.**

## Upgrade

A global install from 1.0.x keeps its database inside the package directory, and `npm install -g` deletes that directory. Copy the data out first.

1. Stop the service. On macOS: `launchctl bootout gui/$(id -u)/com.punchlist`. On Linux: `systemctl --user stop punchlist.service`.
2. Copy the data directory:
   ```bash
   OLD="$(npm root -g)/@aronvaughan/punchlist/data"
   mkdir -p ~/.local/share/punchlist
   cp -a "$OLD/." ~/.local/share/punchlist/
   ```
3. Install the release and write a new service unit:
   ```bash
   npm install -g @aronvaughan/punchlist@1.1.0
   punchlist install-service        # run it under node >= 26
   ```

If you set `PUNCHLIST_DATA` yourself, skip step 2: that value still wins. A source checkout still uses `./data`.

Verify:
```bash
curl -s http://127.0.0.1:8600/api/v1/health   # expect "version":"1.1.0"
punchlist doctor                              # node >= 26, service up, database found
plt list | head -3                            # plt now comes with the package
```

## Breaking changes
- **Data directory of a global install.** It moves from `<package>/data` to `$XDG_DATA_HOME/punchlist`, else `~/.local/share/punchlist`. Why: npm deletes the old directory on upgrade. Migration: follow the upgrade steps above, or set `PUNCHLIST_DATA`.
- **Old node is refused at start.** The engine requirement is still `node >= 26`. The server, `punchlist install-service` and `punchlist doctor` now enforce it. Migration: run `punchlist` under node 26 or later. If your `PATH` leads with an older node, call it by path, for example `$(brew --prefix)/bin/node $(command -v punchlist) install-service`.
- **The Anytime view no longer shows someday tasks.** They moved to a new **Someday** view (`/tasks?view=someday`). Migration: a script that read someday tasks from `view=anytime` must read `view=someday`.
- **The 403 text for approve and answer changed.** It is now `not permitted to approve` and `not permitted to answer`, with no actor name. Migration: a script that matched `only the admin` must match the new text or the 403 status.
- **`plt render index|run|all` renders board pages.** Migration: for a workflow with one of those names, run `plt render --workflow <name>`.
- **The dated design documents left the public tree.** The files `docs/<date>-*.md` and `punchlist-templates/docs/<date>-*.md` are gone. The setup guide, the screenshots and the release notes stay.
- **For contributors: `scripts/install-hooks.sh` writes more hooks.** It adds `post-merge` and `post-checkout` hooks. They reinstall the package globally and restart the service. It refuses to replace a hook that it did not write.

## Changes

### Added
- The process spine in `plt`: `run`, `step`, `receipt`, `gate`, `handoff`, `prime`, `menu` and `config`.
- Cycles `build-and-ship`, `build-and-commit`, `review-pr`, `spike`, `digest` and the `discard` exit, with page templates for each step.
- `plt step block` and `plt step answer`: an agent stops on a question in the ledger and resumes on the answer.
- A `repeat_until` step reopens until it records its outcome. Each round asks for a new approval.
- `plt run close --landed <sha>` closes a run whose work reached the base branch outside its cycle.
- Efforts: `plt effort plan|launch`, a commit-plan page per card, and `plt card rebase` after a merge conflict.
- `plt fan` prints the next parallel wave of a plan. A task that shares a file is held until you pass `--unblock`.
- Boards: `plt render`, `plt publish`, `plt watch` and a launchd or systemd timer for it.
- `plt facts` and `plt run poll` read pull-request state from `gh`.
- `plt digest` for a daily or weekly rollup and a standup.
- `plt sync`, `plt mine`, `plt harvest` and `plt bump` for the improvement loop.
- `plt fsck`, `plt schema`, `plt doctor` and `plt deps`, with five JSON Schemas in `schemas/`.
- `plt lint prose` checks text for long sentences, banned words, ticket keys and undefined acronyms.
- The Claude Code integration: `plt integration install claude` adds hooks and four adversary agents (writing, code, architecture and plan).
- `pl.sh --as <actor>` runs a command as another actor on the server's machine. `--as admin` uses the actor that `PUNCHLIST_ADMIN` names.
- `PUNCHLIST_APPROVERS` and `PUNCHLIST_ANSWERERS` let named agents approve or answer. Both are empty by default.
- A **Someday** view, and quick navigation between projects, date views and agent views.
- A `health-report` template.

### Changed
- `plt` is a bin of the npm package, and the package ships all the files it reads.
- `punchlist install-skills` also installs the `punchlist-templates` skill.
- The service unit pins a stable node path. On macOS, `install-service` now starts the service.
- The logbook loads 50 rows at a time, with a **Load more** button.
- Long review reports and agent questions collapse, with a caret to expand them.
- Step titles wrap. Enter commits a step and opens the next one.
- The KB link sits beside **New task**. A change to `kb_path` moves the SilverBullet space and keeps its login.

### Fixed
- The Today view no longer shows a task twice when it is also due soon.
- Drag reorder in **Manage projects** now accepts a drop after the last row.
- The timeline hides an empty header, and the comment box stays in reach.
- `advance-sweep.sh` runs on macOS. Before, it exited 0 and advanced nothing, because macOS has no `flock`.
- A fresh install no longer writes one copy of an empty database per migration.
- A board page escapes quotes in attribute values.

### Security
- An agent cannot approve or answer unless you name it in `PUNCHLIST_APPROVERS` or `PUNCHLIST_ANSWERERS`. The 403 text no longer names actors.
- The Claude Code integration makes `plt gate approve` an ask rule, so a person approves each human gate.

## Known issues
- The event-driven dispatcher ships turned off (`dispatch_enabled = 0`). The poller still dispatches work.
- Please report other problems at the [issue tracker](https://github.com/aronvaughan/punchlist/issues).
